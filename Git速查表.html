02日常标准流程4 组

第一次使用（只做一次）

git config --global user.name "Your Name"
git config --global user.email "email@example.com"
git config --global --list          # 验证是否生效

开始一个本地项目

git init                      # 初始化仓库
git add .                     # 把所有改动放入暂存区
git commit -m "首次提交"       # 提交到本地仓库
git remote add origin 远程地址 # 关联远程仓库
git push -u origin main       # 首次推送并绑定（之后直接 git push）

拉取别人的项目

git clone 远程地址   # HTTPS 或 SSH 地址均可
cd 仓库名

每天的循环

git pull                   # 1. 先拉，同步远程最新
# ...写代码...
git status                 # 2. 看看改了哪些文件
git add .                  # 3. 暂存
git commit -m "完成xx功能"  # 4. 提交
git push                   # 5. 推送

一句话：推之前先拉，冲突手动解，解完再推。

07撤销与回退3 组 + 口诀

7.1 还没提交：撤销工作区 / 暂存区

git restore 文件丢弃工作区里该文件的修改⚠️ 未提交的改动会真正丢失，无法找回
git restore .丢弃所有工作区修改⚠️ 慎用，未提交的改动全部丢失
git restore --staged 文件把文件移出暂存区，保留工作区修改
git reset HEAD 文件同上，旧版本写法（Git 2.23 之前）
git restore --source=ID 文件把文件恢复到指定提交的版本

7.2 已经提交：回退版本

git reset --soft ID本地仓库回退，暂存区与工作目录保留 → 适合想重新提交
git reset --mixed ID回退并清空暂存区，工作目录不动 → 适合想重新 add（默认模式）
git reset --hard ID回退并清空暂存区 + 工作目录 → 彻底放弃当前修改⚠️ 慎用：未提交的改动直接消失
git reset --hard HEAD^回到上一次提交
git reset --hard HEAD~2回到前两次提交
git reset --hard HEAD丢弃所有未提交改动，提交历史不动

口诀：soft 只动仓库，mixed 再动暂存区，hard 连工作目录一起清空。

7.3 撤销已推送的提交 / 找回丢失的提交

git revert ID生成一次"反向提交"抵消该提交；不改写历史，已推送也能用
git revert HEAD撤销最近一次提交
git reflog查看 HEAD 操作历史（回退、切换等），找到回退前的 ID
git reset --hard ID配合 reflog 里的 ID，回到任意历史状态（后悔药）
08分支13 + 8 条
git branch查看本地分支，* 为当前分支
git branch -r查看远程分支
git branch -a查看本地 + 远程分支
git branch -vv查看分支及其绑定的远程分支

8.1 合并与变基

git merge dev把 dev 合并到当前分支
git merge --no-ff dev合并时强制生成合并提交，保留分支痕迹
git merge --abort放弃本次合并，回到合并前状态
git rebase main把当前分支的提交"搬"到 main 最新提交之后，历史变直线⚠️ 会改写 commit ID，只用于自己的本地分支
git rebase --continue解决变基冲突后继续
git rebase --abort放弃变基，回到变基前状态
git cherry-pick ID把其他分支上的某一次提交"复制"到当前分支
git cherry-pick ID1 ID2一次复制多个提交，按从左到右的顺序应用

merge 与 rebase 的区别

git merge保留分叉、多一个合并提交；commit ID 不变；安全，可用在公共分支
git rebase历史变成一条直线；commit ID 被改写；只用于本地分支

git fetch只把远程更新抓到本地，不合并；可以先用它看看别人改了什么

10忽略文件（.gitignore）模板 + 2 条

在仓库根目录新建 .gitignore，写下的文件/目录不会被追踪，也不会出现在 git status 里。

# 忽略所有 .log、.txt 文件
*.log
*.txt

# ! 表示开例外：这个文件不忽略
!important.txt

# 忽略整个目录
build/
test/

# 只忽略本目录下的 txt（不含子目录）
xxx/*.txt

# 忽略 xxx 目录（含任意层级子目录）里的 txt
xxx/**/*.txt

# 以 / 开头：只匹配仓库根目录下的 config
/config
git check-ignore -v 文件查看是哪条规则忽略了这个文件
git rm --cached 文件让已追踪的文件不再被追踪（本地文件保留）⚠️ 已追踪的文件加入 .gitignore 后不会自动失效，必须先执行这一步
11协作与冲突处理4 组

推送被拒绝

报 ! [rejected] ... (fetch first)：说明远程有别人的新提交，先拉再推。

git pull    # 拉取并合并
# 如有冲突，按下面步骤解决
git push    # 再次推送

冲突文件的标记含义

<<<<<<< HEAD
当前分支的内容
=======
要合并进来的内容
>>>>>>> origin/main

三段标记之间：HEAD 段是自己的改动，下半段是别人的改动，中间 ======= 是分隔线。

解决冲突三步

# 1. 打开冲突文件，只保留想要的内容，删掉 <<<<<<< ======= >>>>>>> 标记
# 2. 标记为已解决
git add 冲突文件
# 3. 提交并推送
git commit -m "解决合并冲突"
git push

想放弃这次操作

git merge --abort合并冲突时，放弃本次合并
git rebase --abort变基冲突时，放弃变基
git cherry-pick --abort优选冲突时，放弃本次 cherry-pick
12危险操作清单7 条
git reset --hard ID丢弃工作区与暂存区的所有未提交改动⚠️⚠️⚠️ 未提交的改动无法找回
git restore 文件丢弃该文件未提交的修改⚠️⚠️ 无法找回
git clean -fd删除所有未追踪的文件和目录⚠️⚠️⚠️ 新建但从未 add 过的文件会直接消失
git push --force用本地历史覆盖远程历史⚠️⚠️⚠️ 可能抹掉他人提交，优先改用 --force-with-lease
git rebase / git commit --amend改写提交历史、产生新的 commit ID⚠️⚠️ 不要对已推送并被他人使用的分支使用
git branch -D dev强制删除未合并的分支⚠️ 该分支独有的提交可能丢失
git rm -r --cached .清空整个索引的追踪记录⚠️⚠️ 容易误伤，执行前确认当前目录正确

🔑 判断标准：只要提交过（git commit），即使 reset --hard 也能用 git reflog 找回；从未提交过的改动，被 restore / clean 删掉就真的没了。

14Git LFS 大文件管理34 条 + 模板

LFS 把大文件存成「指针」，真实内容放进 LFS 存储区，避免仓库被撑爆（GitHub 单文件上限 100 MB）。按 增 → 查 → 改 → 删 → 日常使用 排列。前置：git lfs install 装一次；协作者没装 LFS，克隆下来只会得到一个指针文件。

14.1 安装与启用

winget install GitHub.GitLFSWindows 安装 LFS（或去 git-lfs.com 下载安装包）
brew install git-lfsmacOS 安装
sudo apt install git-lfsUbuntu / Debian 安装
git lfs version确认 LFS 是否安装成功
git lfs install全局启用 LFS（注册 pre-push 等钩子，推荐）
git lfs install --local只对当前仓库启用（克隆别人的 LFS 仓库后可用）

14.2 增：添加追踪规则

git lfs track "*.psd"按后缀追踪，最常用
git lfs track "*.mp4" "*.zip"一次追踪多种类型
git lfs track "data/model.bin"追踪某个具体文件
git lfs track "assets/**"追踪某个目录下的所有文件
git add .gitattributes提交规则文件⚠️ 不提交 .gitattributes，别人拿不到规则，克隆后文件仍是普通文件
git commit -m "配置 LFS"提交规则

顺序不能错：先 track → 再 add 大文件 → 再 commit。规则写在仓库根目录的 .gitattributes 里：

*.psd filter=lfs diff=lfs merge=lfs -text
*.mp4 filter=lfs diff=lfs merge=lfs -text

14.3 查：查看状态与内容

git lfs ls-files列出当前版本被 LFS 追踪的文件
git lfs ls-files -s附带 * / - 标记与文件大小
git lfs ls-files -n只显示文件名，不显示 oid
git lfs ls-files --all列出所有历史版本中出现过的 LFS 文件
git lfs track查看当前生效的追踪规则（读 .gitattributes）
git lfs status查看 LFS 相关的待提交改动
git lfs env查看 LFS 端点、版本等运行环境
git show HEAD:文件输出 version https://git-lfs.github.com/spec/v1 就说明该文件走了 LFS

14.4 改：修改规则 / 改写历史

git lfs track "*.iso"追加追踪规则（等价于再执行一次 track）
git lfs untrack "*.zip"取消某个后缀的追踪；直接删 .gitattributes 里对应行效果相同
git lfs migrate import --include="*.psd,*.mp4"把已经提交的历史整体改写成 LFS 指针⚠️ 会重写历史（commit ID 全变），先用 --dry-run 确认并通知团队
git lfs migrate import --include="*.zip" --include-ref=refs/heads/main只处理指定分支的历史
git lfs migrate export --include="*.mp4" --everything把某类型改回普通 Git 存储
git lfs push --all origin main补传 LFS 对象，修复 missing objects 报错

⚠️ 改规则不影响已经提交的文件：untrack 只对之后的新提交生效，历史里已进入 LFS 的文件仍然留在 LFS。

14.5 删：删除与清理

git rm --cached 大文件.mp4只从 Git 移除追踪，本地文件保留
git rm 大文件.mp4删除文件并记录这次删除
git lfs prune --dry-run先干跑一次，查看能清理多少本地 LFS 缓存
git lfs prune清理本地不再被引用的 LFS 缓存，回收磁盘

⚠️ 删除提交不会让历史里的旧大文件消失，仓库体积也不会变小。

14.6 日常使用与克隆

git add 大文件配好规则后自动走 LFS，日常操作无需额外命令
git clone 远程地址克隆时自动下载 LFS 文件（本机需已装 LFS）
git lfs pull补下载当前版本需要的所有 LFS 文件
git lfs fetch origin main只抓取内容，不检出到工作目录
git lfs checkout把已抓取的 LFS 内容替换到工作目录
git lfs pull --include="assets/*.psd"只下载需要的部分大文件
GIT_LFS_SKIP_SMUDGE=1 git clone 地址克隆时跳过 LFS 文件，只要代码（网慢时用）

PowerShell 下跳过 LFS 的写法：

$env:GIT_LFS_SKIP_SMUDGE=1; git clone 远程地址

14.7 常见问题

大文件只有几十字节，内容是 version https://git-lfs...没装 LFS 客户端或仓库未启用 → git lfs install 后执行 git lfs pull
This exceeds GitHub's file size limit of 100.00 MB大文件没走 LFS 就被提交 → git lfs track 后重新提交；已提交的用 migrate import
推送后别人拿到的还是指针.gitattributes 没提交 → git add .gitattributes 并推送
track 之后文件仍进入普通 Git先 add 了文件、后加的规则 → git rm --cached 文件 后重新 add
LFS upload missing objects本地 LFS 对象没推全 → git lfs push --all origin 分支名
batch response: Authentication required令牌没有 LFS 权限 → 重新生成令牌并勾选 repo

git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.lg "log --all --graph --oneline --decorate"
附commit ID 的简写5 条
a1b2c3d完整或部分 commit ID，一般取前 7 位即可
HEAD当前所在的提交
HEAD^ / HEAD~1上一个提交
HEAD~2前两个提交
分支名该分支的最新提交，如 main、origin/main
没有匹配的内容，换个关键词试试（例如 add、reset、冲突、拒绝）
